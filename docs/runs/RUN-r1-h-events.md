# Run r1-h-events

Branch: agent/r1-h-events. Tasks: T-149 (done, with a producer gap), T-152 (done, with an event gap).

## T-149 Event chain
- Tests prove that unknown and chain-only event types are published or acknowledged and never dead-lettered, in the relay, the pulse consumer and the ml consumer (REQ-EXT-001). No consumer behaviour changes were needed. `ml/consumer.py` was refactored into `process_event` so it can be tested.
- `EVENT_CHAIN_EMIT` (default false) is declared in settings, `.env.example` and `ops/check_configuration.py`. The settings snapshot was regenerated by the coordinator.
- `libs/domain/event_chain.py` gains `chain_events_after(parent, steps, *, enabled)`. It returns [] when the flag is off, so outbox content is unchanged.
- GAP: the six other chain producers are NOT wired. Their call sites (core repository, ML scoring) are outside T-149's write_scope. A follow-up needs a wider scope and must call the helper with `get_settings().event_chain_emit`.

## T-152 Pulse project writers
- `services/pulse/app/project_projection.py` handles `signal.converted_to_project`. It inserts a `project_snapshot` row (stage draft) and the first `project_stage_visit` row, idempotently, with the event tenant.
- GAP: no event carries a later stage change, score, value or burn (`project.pipeline_updated` and `project.forecast_updated` are reserved names only). `exited_at` stays null and the stage stays `draft`. The metrics route shows only counts by stage and service line.
- The SQL was not run against real Postgres, only the SQL-consistency test.
